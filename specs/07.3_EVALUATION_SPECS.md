## 4. Time-aware CV (enhancement 1)

### 4.1 Split

- Sort train by `month` ascending. Reset a 0..n-1 index **after** sort.
- `TimeSeriesSplit(n_splits=5)` on that frame (after `dropna` on features, or dropna **inside** each fold — either is fine if tests still see 5 folds).
- Expanding train prefix, later val block. **No shuffle.**

Per fold, assert in code (and in the unit test):

1. `train_idx` and `val_idx` are strictly increasing.
2. `max(train_idx) < min(val_idx)` and `train.month.max() < val.month.min()`.
3. Fold *k*’s `min(val_idx)` > fold *k−1*’s `min(val_idx)` (later fold is later in time).

### 4.2 No leak across the fold boundary

Causal `shift` on the **full** 2016–2023 frame does not put future *values* into past rows, but a **scaler (or any statistic) fit on all 96 months** leaks later folds. A lag built on a frame that still contains **later-fold** `revenue_usd` is the assignment’s stated risk.

**Required:** for each fold, build the feature frame from rows with `month <= val.month.max()` only (prefix = fold train + that fold’s val). Then `add_causal_features` (or equivalent) on **that prefix**, then slice train/val. Later folds’ `revenue_usd` must not be in the frame.

Also: `StandardScaler` (lag/roll columns only) **fit on fold-train**, `transform` fold-val. Prefer a `Pipeline` + `ColumnTransformer` so `learning_curve` cannot fit the scaler on the future.

Do not use 2024–2025 rows in any prefix.

### 4.3 Report

For each fold: `n_train`, `n_val`, `val_month` start/end, train MAE, val MAE, train RMSE, val RMSE, val RMSE %.

Then **mean ± std** across the 5 val RMSE values **and** the 5 val MAE values (sample std, `ddof=1`). JSON + report. Not a single pooled number.

## 6. MAE vs RMSE (enhancement 3)

Compute MAE and RMSE for **train and validation** (per fold and as CV mean±std). `sklearn.metrics.mean_absolute_error`, `root_mean_squared_error` (or `sqrt(MSE)`).

**Justify in the report which one is the business-primary metric**, using CONTEXT — not a textbook default:

| CONTEXT fact | Implication |
| --- | --- |
| Tom/Sandra want error as **% of average monthly revenue** | A **USD** metric (MAE or RMSE), then `/ mean(revenue_usd)` |
| Sandra’s cost is missing an **atypical August drop** (capacity) vs a normal low season | **Large** misses matter more than typical ±5% months |
| Oct–Dec is **+15–20%** (flu / year-end); Jul–Aug **−12–18%** | Tail months dominate the dollar miss |

**Lock:** primary = **RMSE** (and RMSE %). MAE is the “typical month” companion. Do not pick MAPE or R² as the chosen metric.

## 7. Diagnosis rules (enhancement 4) — compute, then classify

Use **CV val vs train RMSE** and the **learning curve**. Classify exactly one of: `well fitted` | `underfitting` | `overfitting`.

| Signal | Classification |
| --- | --- |
| Train RMSE much lower than val RMSE (e.g. val mean > **2×** train mean) **and** the curve’s train line stays low while val stays high as *n* grows | **overfitting** |
| Train and val RMSE both high **and** close (e.g. both RMSE% **> 12%**, near CONTEXT’s summer swing) **and** the curve does not come down | **underfitting** |
| Modest gap (val < 2× train), val RMSE% in **single digits** (same order as 07.2 holdout ~5–6%), curve flattens together | **well fitted** |

Stability (question 2): `cv_rmse_std / cv_rmse_mean`. If **> 0.35**, say **unstable** when the window moves. CONTEXT: later folds sit on a **higher level** (4% growth, `d` alternates 2–6%). If USD RMSE rises but **RMSE% is flat**, that is scale, not a broken model — say so.

### 7.1 Corrective action (one, specific)

Propose **one** action. Do **not** apply it to the 2024–2025 holdout. Do not change the CSV.

| If you diagnosed | Write this class of action (fill in the actual numbers from *your* CV) |
| --- | --- |
| **overfitting** | Cut capacity so the tree cannot memorize train Jul–Aug / Oct–Dec: e.g. `n_estimators=80`, `max_depth=2` (or `reg_lambda=5`), **keep** `revenue_lag_12`, re-run **train-only** 5-fold CV, stop when val/train RMSE ratio drops. Not “add data” (series is fixed 10 years). |
| **underfitting** | If `revenue_lag_12` / `month_sin` importances are ~0, the model is ignoring CONTEXT seasonality — raise `max_depth` to 4, keep 200 trees, re-CV. Do **not** add same-row visits/ARPV. |
| **unstable**, fit OK | Add a **causal** `years_since_2016` from `month` (no future), re-CV; compare RMSE%. Not “collect more clinics”. |
| **well fitted** | No hyperparameter change. Residual risk: 07.2 plot already under-predicted late-2025 Q4 (growth). Next check is PSI / level, not a deeper tree. |
