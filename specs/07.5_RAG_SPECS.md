# SPECS — 7.5 HealthCore desk knowledge (RAG)

Give **Priya Nair’s 8 patient coordinators** a desk assistant they can query in natural language. Voice: **the clinic’s best service salesperson** — clear, empathetic, never inventing coverage or fees. Answers are **always** generated from retrieved policy text. Never return raw Qdrant hits to a caller.

Authoritative names and documents: [`context/07.5_RAG_CONTEXT.md`](../context/07.5_RAG_CONTEXT.md).

**Out of scope:** LangGraph, patient records, EHR joins, changing the four source policies, sales-forecast / telemetry / `job_runs`, public website.

Implement in this order: **setup → embed → retrieve → query → API → UI → tests → Recall@3 → design doc**.

## 5. Phase 1 — `data/process/rag.py`

### 5.1 `embed(text: str) -> list[float]`

One embeddings model, used for **chunks and questions**. Not the generation model. Prefer the free 4Geeks embeddings model. Normalize whitespace; do not embed empty strings.

### 5.2 `setup() -> int`

1. Read the four Markdown files from `docs/company-knowledge-base/`.
2. Split into **semantic** chunks: prefer `##` / `###` sections; merge orphans that are not a full rule; **never** cut a sentence, numbered rule, or US/UK / Medicare condition in half. Target roughly 200–800 tokens; still ≥ 3 chunks **per file**.
3. Recreate or upsert into `healthcore_knowledge`, Cosine, dim = `len(embed(sample))`.
4. Payload **exactly** (CONTEXT §3 + `text`):

```json
{
  "company": "healthcore",
  "source_document": "insurance-coverage | appointment-policy | referral-process | new-patient-checklist",
  "section": "heading text from the file",
  "language": "en",
  "chunk_index": 0,
  "text": "chunk body"
}
```

5. **Idempotent:** deterministic point IDs `uuid.uuid5(NAMESPACE_URL, f"healthcore:{source_document}:{chunk_index}")`. Re-run upserts the same IDs (no duplicates). Document this in `rag-design.md` (not delete-all unless you also document that).

`setup()` returns the number of points upserted. CLI only calls `setup()`.

## 6. Phase 2 — `data/pipelines/rag.py`

Import `embed` from `data.process.rag`. Do not embed inside the router.

### 6.1 `retrieve(query: str, *, k: int = 5, min_score: float) -> list[dict]`

`embed(query)` → Qdrant top-k → **drop** hits with score `< min_score` → return **payload dicts** (`text`, `source_document`, `section`, `company`, `language`, `chunk_index`) plus optional `score` for logs. **No** Qdrant SDK objects.

Default `min_score` from `RAG_MIN_SCORE` (start ~0.30–0.45 cosine; raise until junk drops, keep Recall@3 ≥ 80%).

### 6.2 `generate_answer(question: str, context: list[dict]) -> str`

Prompt + **generation** LLM only. Instruct:

- Audience: HealthCore **patient coordinator** (Priya’s desk), voice of the best service salesperson.
- Use **only** `context[].text`. Faithfulness: no coverage, fee, or timeframe that is not in the chunks.
- If the question omits country, **distinguish US vs UK** insurance (CONTEXT §6).
- Unlisted insurance: must be **verified with billing** — never confirm undocumented coverage.
- **No-show fees must never be applied to Medicare or Medicaid** (appointment policy, literally).
- Empty `context`: say there is not enough information in the knowledge base — **do not invent**.
- No PHI in the answer.

### 6.3 `query(question: str) -> str`

```text
query = generate_answer(question, retrieve(question, k=5, min_score=...))
```

This is the **only** function HTTP/UI call. LangGraph will later call `retrieve` and `generate_answer` separately — keep them split.

Never return chunk lists or scores from `query()`.

## 7. Phase 3 — `POST /knowledge/query`

`services/api/knowledge/router.py`, mount in `app/main.py` (no extra `/api` prefix — path is `/knowledge/query`).

- Body: `{ "question": "..." }` (non-empty string).
- Response: `{ "answer": "<generated string>" }` only.
- `Depends(get_current_user)` — internal desk tool.
- `from data.pipelines.rag import query` — **no** retrieve/generate copy in the router.
- 4xx/5xx on failure; never a 200 with raw hits. Server logs may include `source_document` + scores, not Qdrant objects.

## 8. Phase 4 — Backoffice `/knowledge`

Authenticated page. Coordinators type a question, submit, see **`answer`**.

- BFF `POST /api/knowledge/query` → FastAPI `POST /knowledge/query` with `Authorization` (same pattern as reporting / inventory).
- Loading: existing `LoadingState` (or disabled submit + “Asking…”).
- Error: `ErrorState` — a failed call must **not** look like an empty answer.
- Match current backoffice slate layout (no new theme system). Nav label: **Desk knowledge**.
- Example placeholders: “Is there a charge for cancelling 12 hours in advance?” / “What do I need to bring to my first appointment?”

## 10. Phase 5b — Recall@3

`data/eval/test-queries.json`: ≥ **8** questions, **all four** `source_document` values (at least two each).

```json
{
  "question": "…",
  "expected_source_document": "appointment-policy",
  "expected_text_contains": "optional substring from the correct chunk"
}
```

No patient names. `scripts/eval_rag_recall.py`: `retrieve(q, k=3, min_score=0)` (or the tuned floor if Recall still ≥ 80%). A hit = a top-3 payload with matching `source_document` and, if set, `expected_text_contains` in `text`. Write `data/eval/rag_recall.json` (`hits`, `n`, `recall_at_3`). **Fail the script if recall < 0.80.**
