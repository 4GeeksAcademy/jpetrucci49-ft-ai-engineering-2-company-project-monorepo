The desk chat waits for a full answer. Stream Claire Whitfield’s compliance assistant token by token, and let the staff member abort that generation and send a new question on the same connection.

**Out of scope:** a new agent, new tools, memory or guardrail changes, LangGraph `interrupt()` / HITL resume, Redis, a second app, and any RFP route.

## 1. Why not LangGraph `messages` mode

`generate_policy` calls `generate_answer`, which posts one non-streaming completion and returns a string. `desk_graph.astream(..., stream_mode="messages")` emits nothing from that call. `values` and `updates` emit a node dict only after the node returns. Do not add a second model client.

Keep `generate_answer(question, context) -> str` for every current caller (`POST /agent/query`, `POST /knowledge/query`, tests). When a stream sink is set for the current task, that same function adds `"stream": true` and yields `choices[0].delta.content` as it arrives. A cancel flag closes the HTTP response and returns the text received so far. No sink: today’s blocking call.

Do not call LangGraph `interrupt()`. Abort means cancel the in-flight task and the HTTP stream.

## 2. One generation, many sockets

Per `session_id`: one producer task, one ordered list of messages, N subscriber queues. A second socket on the same session receives the same frames. It does not start a second graph run.

`POST /agent/query` stays request/response. The socket is an added route on the same router.

| | |
| --- | --- |
| URL | `WS /agent/chat?session_id=<id>&token=<jwt>` |
| Auth | Same JWT as `get_current_user`. Query `token` or a first text frame `{"type":"auth","token":""}`. Close the socket before any chat frame if it is missing or invalid. |
| Bind | `session_id` is required. Unknown id: empty history, then this socket owns it. |

Each graph turn uses a new `thread_id` (`run_id`). Do not resume the aborted thread. `session_id` is the conversation; the message list is what reconnect restores.

## 3. Frames

JSON text frames. `agent_id` is always `compliance_assistant`. `flow_type` is always `chat_session`. `flow_id` is `session_id`.

Client:

```json
{"type":"user_message","text":""}
{"type":"interrupt","new_input":""}
```

`user_message` while a generation is running is an interrupt whose `new_input` is that text.

Server:

```json
{"type":"history","session_id":"","flow_id":"","agent_id":"compliance_assistant","flow_type":"chat_session","messages":[{"id":"","role":"user","text":"","status":"completed"},{"id":"","role":"assistant","text":"","status":"interrupted"}]}
{"type":"token_chunk","session_id":"","message_id":"","text":""}
{"type":"generation_interrupted","session_id":"","message_id":"","status":"interrupted"}
{"type":"generation_completed","session_id":"","message_id":"","status":"completed"}
```

Send `history` immediately after auth, before any live token. Status is `completed` or `interrupted`.

`token_chunk.text` is a delta, not the full answer. On abort: stop further deltas for that `message_id`, store the partial text, set `interrupted`, then if `new_input` is non-empty append that user turn and start a new assistant `message_id`. Do not delete or overwrite the interrupted row.

`generation_completed` fires only if the task finishes. History stores the graph’s final `answer` (after `guard_output`). If that string differs from the concatenated deltas, the completion frame also includes `"text"` and the client replaces the live bubble with it. Otherwise omit `text`.

## 4. Desk page

`DeskKnowledgePage` stops using `POST /api/knowledge/query` for this screen. Open `WebSocket` to the API (`NEXT_PUBLIC_API_WS_URL`, default `ws://127.0.0.1:8000`) at `/agent/chat`. Token from `getToken()` on the query string. `session_id` is a UUID kept in `sessionStorage`.

Show a transcript. Append each delta as it arrives. Sending while a reply is in progress sends `interrupt` with that text as `new_input`. The partial bubble stays, marked interrupted. The next assistant bubble is a new message.

On close: keep the transcript, show **Reconnecting…**, wait 1s, 2s, 4s, 8s, 16s, then 30s. A successful open resets the delay. The server’s `history` replaces the transcript before any new `token_chunk`.

## 5. Tests

`tests/pipelines/test_agent_ws.py`. No live model: the stream sink is fed by a fake that yields a few deltas and stops when cancel is set.

- No token: socket closes before a chat frame.
- One `user_message`: at least one `token_chunk`, then `generation_completed` with a new `message_id`.
- Interrupt mid-stream: no further `token_chunk` for that `message_id`; `generation_interrupted` with `status` `interrupted`; a following `new_input` produces a different `message_id`.
- Two sockets, one `session_id`: both receive the same chunks; the generator runs once.
- Disconnect and connect again with the same `session_id`: `history` contains the interrupted assistant message.

Manual note in `uis/backoffice/README.md`: open `/knowledge`, send a question, send a second question before the first finishes, confirm the first bubble stays marked interrupted and the second answer is a new bubble. Reload the page and confirm the same thread returns.

## 6. PR answers

- Part 1 SSE only sends server events. This chat has to deliver tokens and accept `interrupt` / `new_input` on the same connection while tokens are still arriving. That is a bidirectional channel.
- One producer task per `session_id` publishes to every subscriber queue. A supervisor’s socket does not call the agent again.
- Abort cancels the HTTP stream and the generation task. LangGraph `interrupt()` is not used. The partial assistant message stays with `status` `interrupted`. The next user text starts a new assistant turn.
