# SPECS — 7.6 HealthCore desk agent graph (LangGraph)

Make Priya Nair’s desk RAG **traceable**: compile a graph **before** any run, pass **minimal explicit state**, and persist a **queryable trace** for every execution. Answers must stay grounded in the existing HealthCore knowledge base.

Authoritative policy names: [`context/07.5_RAG_CONTEXT.md`](../context/07.5_RAG_CONTEXT.md). RAG contract: [`specs/07.5_RAG_SPECS.md`](./07.5_RAG_SPECS.md).

**Out of scope:** changing the four policy files, rewriting `embed`/`setup`, merging `retrieve`+`generate_answer` back into one node, LangSmith account required, website, forecast/telemetry/`job_runs`, PHI.

Implement in this order: **state → nodes → conditional edges → compile+checkpointer → traces → evals → HTTP**.

## 3. State (minimal, explicit)

`DeskAgentState` fields — **only** these:

| Key | Type | Who writes | Why |
| --- | --- | --- | --- |
| `run_id` | `str` | intake | Checkpoint + trace filename |
| `question` | `str` | intake | Input to retrieve / generate |
| `context` | `list[dict]` | retrieve node | Payloads from `retrieve()` (`text`, `source_document`, `section`, …) |
| `answer` | `str` | generate **or** refuse | Coordinator-facing string only |
| `error` | `str` | intake (empty question) | Router maps to 400; never a traceback |

**Forbidden in state:** chat `messages`, full conversation history, raw Qdrant SDK objects, embeddings, JWT/user records, PHI.

Do not add a `messages` list “for LangGraph”. This desk turn is one question → one answer.

---

## 4. Nodes (exact names)

Implement in `nodes.py`. Each node reads/writes only the keys it needs.

| Node | Calls | Writes | Must not |
| --- | --- | --- | --- |
| `intake` | none | `run_id`, stripped `question`; `error` if empty | retrieve or generate |
| `retrieve_policy` | `from data.pipelines.rag import retrieve` → `retrieve(question, k=5)` | `context` (list of payload dicts) | `query()`, `generate_answer`, `setup` |
| `generate_policy` | `from data.pipelines.rag import generate_answer` → `generate_answer(question, context)` | `answer` | call `retrieve` or `query()` |
| `refuse` | **none** (no LLM) | `answer` = existing `NO_INFORMATION` from `data.pipelines.rag` | call `generate_answer` or `retrieve` |
| `reject` | none | `error` = `"question must not be empty"`; `answer` = `""` | retrieve or generate |

**Node contract:** `retrieve_policy` only retrieves. `generate_policy` only generates from **already-written** `context`. Putting `query()` (retrieve+generate) in one node **fails** this milestone.

## 5. Edges (conditional — not a straight line)

`START → intake`. Then **two** real predicates (not `add_edge` only):

```text
intake
  ├─ question.strip() == ""     → reject → END
  └─ else                       → retrieve_policy
retrieve_policy
  ├─ len(context) == 0          → refuse → END
  └─ else                       → generate_policy → END
```

`context` empty means `retrieve()` kept **zero** hits above `RAG_MIN_SCORE` (same floor as 07.5). Do **not** send empty context to `generate_policy`.

Wire with `add_conditional_edges` and named routing functions (`route_after_intake`, `route_after_retrieve`) that return the **next node name** as a string.

## 6. Compile before execute

In `graph.py`:

1. `StateGraph(DeskAgentState)` + add the five nodes + conditional edges + `END`.
2. `desk_graph = builder.compile(checkpointer=<MemorySaver>)` at **module import**.
3. Export `desk_graph`. Tests and the router import this object. **Never** `builder.invoke` / compile inside the request handler.

Compilation must fail if a node is added with no path from `START` or a routing function returns an unknown node. Add a unit test that `desk_graph` is already compiled (`invoke`/`ainvoke` exists) and that the graph’s node set is exactly `{intake, retrieve_policy, generate_policy, refuse, reject}`.

---

## 7. Checkpointing

Pass a LangGraph checkpointer into `compile`. Every node return is a checkpoint.

- `configurable.thread_id` = `run_id` (UUID4 from `intake`).
- After `invoke`, `desk_graph.get_state(config)` must show the final `question` / `context` / `answer` / `error`.
- Tests: run with a checkpointer; assert `get_state` matches the invoke result.

MemorySaver is required. Sqlite/Postgres checkpointers are optional.

## 8. Trace (queryable, not stdout-only)

After each `invoke` (success or routed refuse/reject), write:

`data/eval/agent_traces/{run_id}.json`

```json
{
  "run_id": "uuid",
  "path": ["intake", "retrieve_policy", "generate_policy"],
  "question": "…",
  "context_sources": ["appointment-policy"],
  "answer": "…",
  "error": null
}
```

| Field | Rule |
| --- | --- |
| `path` | Node names in execution order (no `START`/`END`) |
| `context_sources` | `source_document` values from `context` (may be `[]`) |
| `answer` | Final coordinator string (or `""` on reject) |
| `error` | `null` or the reject message |

Append-only files. `GET /agent/traces/{run_id}` reads that file (404 if missing). Do not return chunk `text` on the trace HTTP if you can avoid it — sources + path + answer are enough. Server-side file may include `source_document` list only.

LangSmith is optional. A structured file store **is** the acceptance trace.

Build `path` from checkpoint history or by recording the node name at the start of each node (write a `path: Annotated[list[str], add]` **only if** you keep it a reducer of node names — still not conversation history). Prefer recording in a small `trace_run(state)` helper after invoke from checkpoint values + known route, or have each node append its own name to `path`.

If you add `path` to state: it is a list of **node ids**, not messages.

## 9. Evals (`tests/pipelines/test_agent_graph.py`)

Single command (repo root):

```bash
uv run python -m pytest tests/pipelines/test_agent_graph.py tests/pipelines/test_rag.py
```

Evals **read traces** (`data/eval/agent_traces/*.json`). They must not require a live LLM/Qdrant on every pytest. Commit at least **three** fixture traces (or generate them in-process with **mocked** `retrieve` / `generate_answer`, then persist and assert). Live `invoke` against Qdrant/LLM is allowed in a separate optional test, not as the only eval.

### Required evals (minimum 3)

| ID | Input (in fixture) | Assert on **trace** |
| --- | --- | --- |
| `path_retrieve_before_generate` | CONTEXT cancellation question: *Is there a charge for cancelling 12 hours in advance?* | `path` contains `retrieve_policy` then later `generate_policy`; `retrieve_policy` index < `generate_policy` index |
| `path_empty_skips_retrieve` | `question` `""` or whitespace | `path` is `["intake", "reject"]`; `retrieve_policy` **absent**; `error` set |
| `path_no_hits_refuses` | Off-policy question (e.g. weather) with empty `context` | `path` ends with `refuse`; `generate_policy` **absent**; `answer` contains “don't have” / “enough information” (same idea as `NO_INFORMATION`) |
| `grounded_no_show_medicare` (**required grounding**) | *Do Medicare or Medicaid patients pay a no-show fee?* | `answer` must **not** apply the 50 USD / 40 GBP private-pay no-show fee to Medicare/Medicaid; must match appointment-policy (no fee). `context_sources` includes `appointment-policy` **or** (if fixture used mocks) `answer` states they are **not** charged |

Grounding is an **acceptance gate**. A perfect `path` with an answer that invents coverage or charges Medicare a no-show **fails**.

Do not delete or weaken `tests/pipelines/test_rag.py`.

## 10. HTTP

`services/api/agent/router.py`, mount in `app/main.py` (no extra `/api` prefix).

### `POST /agent/query`

- `Depends(get_current_user)` (same desk JWT as `/knowledge/query`).
- Body: `{ "question": "..." }`.
- Handler: create no graph; `desk_graph.invoke({...}, config={"configurable": {"thread_id": run_id}})` then persist trace.
- Success **200:** `{ "answer": "<string>", "run_id": "<uuid>" }`. Never chunks, scores, or state dump.
- Empty question: **400** `{ "detail": "question must not be empty" }` (from `error` or pre-check). Prefer letting `intake`→`reject` set `error` and mapping that in the router.
- Graph/node failure: **503** `{ "detail": "<short reason>" }`. Reuse the 07.5 pattern: `RuntimeError` → 503 message; other exceptions → generic 500 **without** traceback in the body. Existing `unhandled_exception_handler` already sanitizes 500s — do not bypass it with `str(exc)` on unknown errors.

### `GET /agent/traces/{run_id}`

- JWT required.
- **200** the JSON file. **404** if missing.
- No stack traces.

`/knowledge/query` remains for 07.5.
