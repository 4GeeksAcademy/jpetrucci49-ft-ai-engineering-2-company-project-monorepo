# SPECS — 7.7 stretch: desk agent inventory lookup

Optional second tool: coordinators ask *do we have stock of X?* The compiled desk graph already routes RAG vs incidents ([`specs/07.7_LANGGRAPH_TOOL_SPECS.md`](./07.7_LANGGRAPH_TOOL_SPECS.md)). Add a **separate** inventory tool. Do not merge ticket lookup and stock lookup into one function.

**Out of scope:** inbound/outbound orders, creating supplies, rewriting 07.7 incident nodes, RAG `setup`/`embed`/`query`, website, PHI.

Implement in this order: **typed tool → classify + inventory nodes → edges → traces → evals**. HTTP stay `{ question }` → `{ answer, run_id }`.

## 2. Transport

Same package as the API. **In-process:**

```text
from inventory.database import get_session_factory
from inventory.service import list_supplies, get_supply
```

Open one `Session` per lookup, close it in `finally`. Do **not** HTTP-loop to `:8000`. Do **not** ship a hardcoded catalogue in the agent.

Tests mock `list_supplies` / `get_supply` (or the tool’s thin wrappers). Production must still call those service functions.

**Auth:** `GET /inventory/products` requires the desk JWT. The tool takes no token (request already authenticated). State that in the PR. `SUPABASE_DATABASE_URL` (or the local SQLite URL) is required for a live lookup; missing DB → `unavailable`, not invented stock.

## 3. Typed contract

`services/api/agent/tools/inventory.py` — Pydantic only.

### Input — `InventoryLookupIn`

| Field | Type | Rule |
| --- | --- | --- |
| `supply_id` | `int \| None` | If the question has `supply 3` / `product 3` |
| `sku` | `str \| None` | Exact SKU if present (`HCR-PPE-001`) |
| `name_query` | `str \| None` | Remaining product words (`nitrile gloves`, `strep`) |

If `supply_id` is set, call `get_supply(session, id)` only. Else `list_supplies(session)` then filter (do **not** dump the full catalogue to the coordinator).

No id, sku, or name_query → `not_found` (do not list every SKU).

### Output — `InventoryLookupOut`

| Field | Type | Rule |
| --- | --- | --- |
| `ok` | `bool` | `True` only when ≥1 matching row |
| `supplies` | `list[SupplyRecord]` | Empty on miss / timeout / error |
| `error` | `Literal["not_found", "timeout", "unavailable"] \| None` | Never a traceback |

`SupplyRecord` fields — **exactly** `MedicalSupplyResponse`:

`id`, `name`, `sku`, `category`, `unit`, `country`, `current_stock`

Cap filtered matches at **5**. Prefer SKU exact match, then case-insensitive `name` substring.

## 4. Tool behaviour

| Rule | Detail |
| --- | --- |
| Read-only | Call **only** `list_supplies` and/or `get_supply`. Importing `create_supply`, `register_delivery`, or `register_consumption` in this module **fails**. |
| Timeout | `INVENTORY_LOOKUP_TIMEOUT_SECONDS = 5` (env override, same name). Wrap the service call (`concurrent.futures`). On expiry: `ok=False`, `error="timeout"`. |
| Other errors | `SupplyNotFoundError` → `not_found`. Missing/invalid DB URL or unexpected exception → `unavailable`. Log; do not put `str(exc)` in state or the answer. |
| Stock truth | Use `current_stock` from the service response. Do not invent quantities. |

## 5. Classify (extend 07.7, still no extra LLM)

Keep existing `rag` / `incident` / `both` (both = incident + RAG).

**Add** `inventory` and `inventory_rag`.

Stock ask: `\b(stock|inventory|sku|supply|supplies|gloves|in stock)\b` or a known seed name/SKU fragment (`nitrile`, `HCR-`).

| `intent` | When |
| --- | --- |
| `inventory` | Stock ask and **not** a policy question and **no** ticket id |
| `inventory_rag` | Stock ask **and** policy (e.g. cancellation + gloves) |
| existing `incident` / `both` | Ticket id or ticket words — **unchanged**. Ticket + stock in one question stays on the **incident** path (do not chain a third tool this stretch). |
| `rag` | Default when no ticket and no stock ask |

Parse `InventoryLookupIn` in classify (or a sibling `parse_inventory_lookup`). No I/O.

## 7. Nodes (exact names)

Keep every 07.7 node. **Add:**

| Node | Does | Must not |
| --- | --- | --- |
| `lookup_inventory` | Call the inventory tool; write `inventory_result` | Call incident manager, retrieve, generate, or write APIs |
| `answer_inventory` | Coordinator string from `inventory_result` only (template; no LLM) | Invent `current_stock` |
| `refuse_inventory` | Fixed fallback below | Guess stock |

`classify` also writes `inventory_query` (empty when unused).

`generate_policy` / `refuse`: if `intent == inventory_rag`, append the stock sentence or the inventory fallback — same pattern as incident `both`.

## 8. Edges

Extend `route_after_classify` only (intake / incident / retrieve edges stay):

```text
classify
  ├─ incident | both     → lookup_incident     (07.7)
  ├─ inventory           → lookup_inventory
  ├─ inventory_rag       → lookup_inventory
  └─ rag                 → retrieve_policy
lookup_inventory
  ├─ intent == inventory and result.ok     → answer_inventory → END
  ├─ intent == inventory and not result.ok → refuse_inventory → END
  └─ intent == inventory_rag               → retrieve_policy
```

Named router: `route_after_inventory`.

## 9. Copy

Fallback (exact):

```text
I couldn't confirm that supply's stock right now
```

Success template (labels, not raw slugs): category `ppe` → `PPE`; country `US`/`UK` as **United States** / **United Kingdom**. Include `name`, `sku`, `current_stock`, `unit`. Example: `Nitrile gloves (box of 100) (HCR-PPE-001): 40 box on hand (United States).`

Zero stock is a real number — say `0`, do not treat as `not_found`.
