## 2. What a good model means here (CONTEXT §3)

| Metric | HealthCore meaning |
| --- | --- |
| **Gini** | Sandra: rank a **normal August low-season** month vs an **atypical drop** (e.g. capacity). High Gini = useful ranking. |
| **PSI** | Detect **train vs test shift**. CONTEXT’s intent is US/UK **visit mix** (e.g. a new clinic). File has no US/UK rows — compute PSI on `visits_count` (and on scores/revenue as required below) and **say so** in the README. |
| **MSE** | Report **USD²** and as a **% of average monthly revenue** (Tom/Sandra: no extra translation). Use `100 * sqrt(MSE) / mean(y_test)` as that percentage (RMSE / mean revenue). |
| **K2 Score** | Assignment name. Implement as two-sample **KS statistic** `ks_2samp(y_test, y_pred).statistic`. |

README (or comments) must explain each metric and **why low MSE alone is not enough**: MSE is scale-dependent; it does not prove ranking (Gini), distributional stability (PSI), or that predicted vs actual CDFs match (K2).

### 5.3 Causal features (mandatory)

Engineer on the **sorted full series**, then split. History for 2024-01 may include 2023-01. A feature that uses row `t`’s `revenue_usd` (or later) **fails the milestone**.

| Feature | Rule |
| --- | --- |
| `revenue_lag_1` | `revenue_usd.shift(1)` |
| `revenue_lag_12` | `revenue_usd.shift(12)` — annual seasonality (Jul–Aug / Oct–Dec) |
| `revenue_roll_mean_3` | `revenue_usd.shift(1).rolling(3).mean()` — **shift before rolling** |
| `month_num` | 1–12 from `month` |
| `month_sin`, `month_cos` | `sin/cos(2π * month_num / 12)` |

Optional: `visits_lag_1` = `visits_count.shift(1)` only.

**Forbidden:** unshifted `rolling`; `shift(-1)`; same-row `visits_count` / `avg_revenue_per_visit_usd`; encoding `region` as a current-row dummy when the file is all `consolidated` (zero variance).

### 5.4 Split then scale (CONTEXT §6 + assignment)

| Set | `month` |
| --- | --- |
| Train | `2016-01-01` … `2023-12-01` (96 months, first **8 years**) |
| Test | `2024-01-01` … `2025-12-01` (24 months, last **2 years**) |

`train.month.max() < test.month.min()`. No overlapping months. Never fit or scale on test.

1. Split after features.
2. Drop NaN features on train; test must stay **24** rows (lags exist from 2016–2023).
3. `StandardScaler` (or `MinMaxScaler`) **fit on train features only**, `transform` test. Keep **unscaled** `revenue_usd` for MSE. Scale lag/roll columns so they are not compared raw to `month_num`.

## 7. Evaluation (test set)

Implement in `data/process/sales_forecast.py`; print from the CLI; write `data/eval/sales_forecast_metrics.json`.

| Name | Compute |
| --- | --- |
| **MSE** | `mean_squared_error(y_test, y_pred)` (USD²) plus `% of average monthly revenue` = `100 * sqrt(MSE) / mean(y_test)` |
| **PSI** | 10 equal-width bins from **train**; compare train vs test masses. `Σ (test_i - train_i) * ln(test_i / train_i)` with epsilon. Primary: `visits_count` train vs test (CONTEXT visit-mix). Also report PSI on predicted (or actual) **`revenue_usd`**. Note: no US/UK rows in the file. |
| **Gini** | `2 * roc_auc_score((y_test > y_test.median()).astype(int), y_pred) - 1` — ranking, not dollar error |
| **K2 Score** | `scipy.stats.ks_2samp(y_test, y_pred).statistic` |

## 10. Tests — `tests/pipelines/test_sales_forecast.py`

No live API. Use the real CSV (same column names).

1. **`test_train_test_split_eight_and_two_years`** (CONTEXT §6)
   - Train 2016–2023, test 2024–2025; 96 / 24 rows before lag-NaN drop.
   - `train["month"].max() < test["month"].min()`; disjoint `month` sets (no leakage of test months into train).
   - After `dropna` on features, test still 24 rows.

2. **`test_lag_and_rolling_are_causal`** (assignment)
   - For a known `t` (e.g. `2018-01-01`): `revenue_lag_1` == revenue at `2017-12-01`; `revenue_lag_12` == `2017-01-01`; `revenue_roll_mean_3` == mean of `t-1, t-2, t-3` **not** `t`.
   - `revenue_lag_1` ≠ current `revenue_usd` on a month where they differ.

Optional assert: all `revenue_usd` > 0; 120 consecutive months.
