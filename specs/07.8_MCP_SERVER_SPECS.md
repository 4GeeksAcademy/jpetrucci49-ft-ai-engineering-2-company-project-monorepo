# SPECS — 7.8 HealthCore MCP server + desk-agent client

Expose Incidents Manager and inventory as an **independent MCP server** (OAuth via [MCP Auth](https://mcp-auth.dev/), package `mcpauth`). Then make the desk agent consume **incidents only through that server**. Direct `get_incident` / `list_incidents` / `create_incident` / `update_incident_status` from `services/api/agent/` **fails** this ticket.

Graph routing (RAG vs tools) stays [`specs/07.7_LANGGRAPH_TOOL_SPECS.md`](./07.7_LANGGRAPH_TOOL_SPECS.md) + stretch. HTTP stays `{ question }` → `{ answer, run_id }`.

**Out of scope:** website, forecast, rewriting RAG, FastMCP’s built-in `AuthSettings` / `token_verifier`, stdio as the production transport, a second incident store.

Implement in this order: **MCP server + scopes → inventory reject tool → discovery docs → agent MCP client → delete direct IM path → evals**.

## 2. Transport (locked)

Use **Streamable HTTP**, not stdio.

| Why | Implication |
| --- | --- |
| Playground, the desk agent, and future clients are **remote** | Need a URL + `Authorization: Bearer` |
| OAuth 2.1 resource-server mode | PRM + JWT on HTTP; stdio has no bearer challenge |
| Codespaces → MCP Playground | Bind `0.0.0.0`, port **8100** (API stays 8000) |

`stateless_http=True` on FastMCP. Resource identifier (`MCP_RESOURCE`) is an `https?://` URL **without a fragment**, and it **must match** the token `aud` (RFC 8707). In Codespaces that is the **public forwarded** origin (e.g. `https://<id>-8100.app.github.dev/mcp`), not `http://127.0.0.1:8100`.

## 4. OAuth (MCP Auth — mandatory)

Package: **`mcpauth`**. Resource-server mode. Do **not** pass `auth=` / `token_verifier=` into `FastMCP(...)`.

At startup:

```text
from mcpauth import MCPAuth
from mcpauth.config import AuthServerType
from mcpauth.types import ResourceServerConfig, ResourceServerMetadata
from mcpauth.utils import fetch_server_config
```

1. `fetch_server_config(os.environ["MCP_AUTH_ISSUER"], AuthServerType.OIDC)` (or `OAUTH` if the issuer is not OIDC).
2. `MCPAuth(protected_resources=[ResourceServerConfig(metadata=ResourceServerMetadata(resource=MCP_RESOURCE, authorization_servers=[…], scopes_supported=[…]))])`.
3. Mount `*mcp_auth.resource_metadata_router().routes` (RFC 9728 `/.well-known/oauth-protected-resource` …).
4. Mount FastMCP under `/` or `/mcp` with  
   `Middleware(mcp_auth.bearer_auth_middleware("jwt", resource=MCP_RESOURCE, audience=MCP_RESOURCE, required_scopes=["incidents:read"]))`  
   so **list and call** require a valid JWT. Tools that write then check **additional** scopes (below).

Unauthenticated `tools/list` or `tools/call` → **401** + `WWW-Authenticate` pointing at the PRM URL. Missing scope → **403** `insufficient_scope` (middleware) or a tool error that **names** the missing scope.

Inside tools: `mcp_auth.auth_info` (`subject`, `client_id`, `scopes`). Never log the raw token.

### Scopes (least privilege)

Advertise exactly these in `scopes_supported`:

| Scope | Tools |
| --- | --- |
| `incidents:read` | `incidents_get` (and list-if-you-add-it) |
| `incidents:write` | `incidents_create`, `incidents_update_status` |
| `inventory:read` | `inventory_query`, and the **reject** tool (so a client can *see* the deny) |

Do **not** advertise `inventory:write`. A write-shaped inventory tool still exists and **rejects** (see §6).

The agent client token needs `incidents:read` (lookup). Create/update scopes are for Playground / operators, not the desk graph.

## 5. Incident tools (real manager)

In-process: `from app.incidents.manager import create_incident, get_incident, update_incident_status`. Same TinyDB as the API (`INCIDENTS_DB_PATH` / default `incidents.json`). No HTTP loop to `:8000`.

| Tool name | Scope | Input (API names) | Calls |
| --- | --- | --- | --- |
| `incidents_get` | `incidents:read` | `incident_id: int` | `get_incident` |
| `incidents_create` | `incidents:write` | `title`, `description`, `category`, `origin`, `branch` (enums as in `IncidentCreate`; default status `open`) | `create_incident` |
| `incidents_update_status` | `incidents:write` | `incident_id: int`, `status: IncidentStatus` | **`update_incident_status` only** — never a generic field patch |

Illegal transitions use the manager `ValueError` (`Cannot change status from 'open' to 'resolved'.`). Map to tool error `invalid_status_transition`. Missing id → `incident_not_found`.

Descriptions must state HealthCore enums and the lifecycle (`open` → `in_progress`\|`discarded`; `in_progress` → `resolved`\|`discarded`; terminals have no next).

## 6. Inventory tools (read-only **by rejection**)

In-process: `list_supplies` / `get_supply` + `get_session_factory()`. Fields = `MedicalSupplyResponse`.

| Tool name | Behaviour |
| --- | --- |
| `inventory_query` | Scope `inventory:read`. Input: `supply_id` and/or `sku` and/or `name_query` (same idea as 07.7 stretch). Cap 5. Uses `current_stock` from the service. |
| `inventory_mutate` | **Registered** (discoverable). Description: *HealthCore inventory is query-only. This tool always fails.* Any call returns a **tool error** (not a silent no-op) with code `inventory_read_only`. Must **not** import `create_supply`, `register_delivery`, or `register_consumption`. |

Omitting write tools is **not** enough.

## 7. Discovery

Each tool: **name**, **description** (who it is for, which HealthCore system, what it will not do), **JSON schema** for args (enum values listed). Output: JSON matching `IncidentPublic` or `MedicalSupplyResponse` (ISO datetimes).

`mcps/healthcore/README.md` is the human `--help`: URL, PRM path, scopes, tool table, error codes.

## 8. Errors and logs

Document in the README (HTTP vs tool payload):

| Code | When | HTTP / tool |
| --- | --- | --- |
| `invalid_token` | Missing/bad JWT | **401** |
| `insufficient_scope` | Valid JWT, wrong scopes | **403** |
| `incident_not_found` | Unknown id | tool error |
| `invalid_status_transition` | Lifecycle reject | tool error |
| `validation_error` | Bad enum / empty title | tool error |
| `inventory_not_found` | No matching SKU/name/id | tool error |
| `inventory_read_only` | Any `inventory_mutate` call | tool error |
| `unavailable` | DB/TinyDB down | tool error |

Every invocation: log `tool`, `client_id`, `subject`, `result` (`ok` or error code). No token, no PHI, no full description dumps.

## 9. Agent migration

`lookup_incident` must **not** import `app.incidents.manager`. Use [`langchain-mcp-adapters`](https://github.com/langchain-ai/langchain-mcp-adapters) `MultiServerMCPClient` (Streamable HTTP) against `MCP_SERVER_URL`, header `Authorization: Bearer <token>`.

Token for the agent: client-credentials (or the provider’s machine-to-machine grant) using `MCP_CLIENT_ID` / `MCP_CLIENT_SECRET` against the issuer token endpoint. Cache the access token. **Never** hardcode a JWT. Tests mock the MCP client / `incidents_get`.

| Keep in `agent/tools/incidents.py` | Remove from the agent package |
| --- | --- |
| `classify_question`, `parse_incident_lookup`, formatters, `IncidentLookupIn` | `get_incident`, `list_incidents`, `lookup_incidents` calling the manager |

`lookup_incident` node: map `incident_query` → MCP `incidents_get` (timeout still 5s). Same `incident_result` shape so traces/evals stay valid. `classify` / RAG edges unchanged.

Inventory graph node: switch to MCP `inventory_query` **or** keep 07.7 in-process — ticket only forbids a second **incident** path. Prefer MCP for inventory too so one client.

If the MCP server is down: same coordinator fallback as 07.7 (`I couldn't confirm that ticket's status right now`), `incident_error` `unavailable` / `timeout`.
