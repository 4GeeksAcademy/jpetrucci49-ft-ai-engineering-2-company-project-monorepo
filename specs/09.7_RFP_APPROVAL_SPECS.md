# SPECS — 9.7 RFP approval and completion (Milestone 9 Part 3 of 3)

Each department owner signs their own section. The flow pauses only that branch, then compiles one final document after all three approvals. Dedicated `rfp_approval` LangGraph. Same FastAPI process. Same ticket row. Postgres/SQLModel remains the source of truth.

Authoritative domain: [`context/09.5_CONTEXT.md`](../context/09.5_CONTEXT.md) (this repo has no `CONTEXT-company.md`). Do not edit `context/**`. Approvers are only the §2.1 owners. Compliance must approve before close. It does not co-sign the other sections.

**Out of scope:** a new API process, nodes on `desk_graph` / `rfp_intake_graph` / `rfp_draft_graph`, re-parsing the PDF, LLM voting among agents, setting `discarded` because a human rejected a section or the Part 3 cap was hit.

**Read:** `context/09.5_CONTEXT.md` §2.1, §5, §7; `specs/09.6_RFP_RESPONSE_SPECS.md` (`part2_handoff_json`); `services/api/rfp/models.py`; `contains_phi` in `services/api/agent/memory/phi.py`; `generate_section` in `data/pipelines/rfp_draft/generate.py` (reuse it for `request_changes`; do not re-run the Part 2 graph).

Leave `handoff_json` and `part2_handoff_json` read-only.

## 1. Rules

**Entry:** `part2_handoff_json` is set and `status` is `under_evaluation` or `needs_human_review`. Capped Part 2 sections enter Part 3 as provisional drafts. They are not auto-approved.

| `department_id` | `approver` stored |
| --- | --- |
| `revenue` | Tom Callahan |
| `clinical` | Dr. Marcus Reid |
| `compliance` | Claire Whitfield |

The backoffice user submits the decision. `approver` is the owner name above, not the JWT email.

| Status this part may set | When |
| --- | --- |
| `waiting_for_approval` | Any department approval is still open |
| `done` | `final_document_json` stored. All three `approved`. No blocking trigger. Compliance approved. No section `contains_phi` |

| Decision | Effect on that branch only |
| --- | --- |
| `approve` | `approval_status=approved`, `approver` = owner, `approved_at` = now. Refused while `blocking_triggers` is non-empty. |
| `request_changes` | `approval_status=changes_requested`. `generate_section` for this department with the comment as feedback, then interrupt again. |
| `reject` | `approval_status=rejected`. No auto-revise. No final document. Ticket stays `waiting_for_approval`. A later `request_changes` on the same thread may reopen it. |

Comment required for `request_changes` and `reject`.

**Cap:** `MAX_APPROVAL_ITERATIONS = 3` `request_changes` rounds per department. On cap: stop revising, section stays unapproved, ticket stays `waiting_for_approval`, trace records `approval_iteration_cap`.

**Threads:** parent `rfp-{ticket_id}`, branch `rfp-{ticket_id}:{department_id}`. A parent `interrupt()` that waits for all three is forbidden. Resuming one department must not resume another.

**Checkpointer:** durable `SqliteSaver` under `data/raw/` (gitignored). Not `MemorySaver`. Tests use a temp sqlite file.

**Crash:** `error_code=approval_pipeline_error` (no PHI). Leave `waiting_for_approval` if a branch had started. Retry start only when no department thread is waiting.

**PHI:** before show or final-document write, `contains_phi` replaces the draft with `Content blocked pending Compliance review.` and sets `contains_phi: true`.

## 3. Graph

```text
guard (PHI, BAA/DPA, currency — no interrupt)
  → arbitrate (only if a §7 trigger matches)
  → interrupt(approval_payload)
  → Command(resume=decision):
       approve → branch_done
       request_changes (iteration < 3) → generate_section(this dept) → guard → interrupt
       request_changes (iteration == 3) → cap, stay unapproved
       reject → stay open
```

Interrupt payload (this section only):

```text
{
  "ticket_id": "",
  "department_id": "compliance",
  "owner": "Claire Whitfield",
  "client_name": "",
  "client_country": "US",
  "currency": "USD",
  "covered_population": 800,
  "draft_content": "",
  "evaluation_results": {},
  "needs_human_review": false,
  "open_questions": [],
  "blocking_triggers": []
}
```

`blocking_triggers` lists §7 ids still true for this section. Empty means approve is allowed.

Parent starts the three branch invokes, sets `waiting_for_approval`, and returns. After each resume, join on `rfp-{ticket_id}`: all three approved and no blocking trigger → synthesize → `done`; otherwise stay `waiting_for_approval`.

Resume entry: `graph.invoke(Command(resume=decision), config={"configurable": {"thread_id": "rfp-{ticket_id}:{department_id}"}})`.

## 4. Arbitration (CONTEXT §7)

One node, `arbitrate`. No LLM. `phi-detected` wins over the other triggers.

| `trigger_id` | Fire when | Arbiter | Action |
| --- | --- | --- | --- |
| `phi-detected` | `contains_phi` on a draft, or `evaluation_results.compliance.contains_phi` is true | Claire Whitfield | Blocked stub. `request_changes` on every offending section. Synthesizer does not run. |
| `baa-dpa-mismatch` | US compliance text lacks `BAA` / `Business Associate`; UK lacks `DPA` or `UK GDPR`; or a section quotes `GBP` on a US client or `USD` on a UK client. Part 2 rule ids `baa-us`, `dpa-uk`, `currency-country` count. | Claire Whitfield | `request_changes` on `compliance` and any section with the wrong instrument or currency. |
| `capacity-vs-population` | An integer sits within 40 characters after `staff capacity`, `clinic count`, or `headcount` in the clinical `key_aspects` or draft, and that integer is below `covered_population`. No such number → do not fire. Only after `phi-detected` is clear. | Tom Callahan | `request_changes` on `clinical` and `revenue`. Instruction: reduce covered population or add sites. Do not invent the new figure. |

```text
{
  "trigger_id": "baa-dpa-mismatch",
  "arbiter": "Claire Whitfield",
  "arbiter_department_id": "compliance",
  "affected_departments": ["compliance"],
  "action": "request_changes",
  "instruction": "US client requires a Business Associate Agreement (BAA) clause."
}
```

An `approve` while `blocking_triggers` is non-empty is refused. The branch stays interrupted. The response names the `trigger_id`.

## 7. HTTP (existing `/rfp`, JWT)

| Method | Path | Behavior |
| --- | --- | --- |
| `POST` | `/rfp/tickets/{id}/approvals` | **202** `{ticket_id, status: waiting_for_approval}`. **409** if the Part 2 handoff is missing or status is not an entry status. |
| `POST` | `/rfp/tickets/{id}/approvals/{department_id}` | Body `{decision, comment?}`. Resume that thread, then join. **400** bad decision, missing comment, or blocked approve. **409** if that thread is not waiting. |
| `GET` | `/rfp/tickets/{id}` | Add `final_document_json` when set |
| `GET` | `/rfp/tickets/{id}/sections` | Add `approval_status`, `approver`, `approved_at` |

## 8. Backoffice `/rfp`

**Start department approval** when Part 2 handoff is set and status is `under_evaluation` or `needs_human_review`.

While `waiting_for_approval`, poll. Each card shows the interrupt payload and **Approve**, **Request changes**, **Reject**. An approved branch has no second approve. Page intro stays generic. Owner names stay on the cards.

When `done`, show client, currency, and the three approved sections.

BFF: `POST /api/rfp/tickets/[ticketId]/approvals` and `POST /api/rfp/tickets/[ticketId]/approvals/[departmentId]`.
