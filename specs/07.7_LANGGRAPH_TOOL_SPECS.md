# SPECS — 7.7 Desk agent incident lookup tool

Give Priya Nair’s coordinators a **read-only** incident lookup on the same compiled desk graph. The graph decides from the **question text** whether to use RAG, the incident tool, or both. The user never names a source.

Authoritative policy: [`context/07.5_RAG_CONTEXT.md`](../context/07.5_RAG_CONTEXT.md). Incident fields: [`context/11_CONTEXT.md`](../context/11_CONTEXT.md). Graph contract: [`specs/07.6_LANGGRAPH_SPECS.md`](./07.6_LANGGRAPH_SPECS.md).

**Out of scope:** inventory tools, writing incidents, rewriting RAG `setup`/`embed`/`query`, website, forecast/telemetry, PHI, a second fake incident store.

Implement in this order: **typed tool → classify + lookup nodes → conditional edges → traces → evals**. HTTP stay `{ question }` → `{ answer, run_id }`.

## 2. Transport (required: real store)

The incident manager is **in the same FastAPI package**. Implement the tool **in-process**:

```text
from app.incidents.manager import get_incident, list_incidents
```

Do **not** HTTP-loop back to `127.0.0.1:8000` (deadlock risk under one worker). Do **not** ship a parallel JSON/list of fake tickets inside the agent.

Tests may **mock** `get_incident` / `list_incidents`. The production function must still call those symbols.

**Auth:** `GET /api/incidents*` requires the same desk JWT as `POST /agent/query`. The tool does not take a token: the HTTP request is already authenticated; the in-process layer has no auth of its own. State that in the PR. Never hardcode a JWT.

## 3. Typed contract

`services/api/agent/tools/incidents.py` (or `agent/tools.py` if you keep one module). Pydantic models, not loose dicts.

### Input — `IncidentLookupIn`

| Field | Type | Rule |
| --- | --- | --- |
| `incident_id` | `int \| None` | Primary. Parsed from the question (`#12`, `ticket 12`, `incident 12`). |
| `status` | `IncidentStatus \| None` | Optional filter when **no** id. Same enum as the API. |
| `category` | `IncidentCategory \| None` | Optional filter when **no** id. |
| `origin` | `IncidentOrigin \| None` | API name is **`origin`**, not `source`. |
| `branch` | `IncidentBranch \| None` | Optional filter when **no** id. |

One tool. If both `incident_id` and filters are set, **id wins** (`get_incident` only).

### Output — `IncidentLookupOut`

| Field | Type | Rule |
| --- | --- | --- |
| `ok` | `bool` | `True` only when at least one real row was returned |
| `incidents` | `list[IncidentRecord]` | Empty on miss / timeout / error |
| `error` | `Literal["not_found", "timeout", "unavailable"] \| None` | Never a traceback |

`IncidentRecord` fields — **exactly** the public API (same names):

`id`, `title`, `description`, `category`, `status`, `origin`, `branch`, `created_at`, `updated_at`

Serialize datetimes as ISO-8601 strings.

## 4. Tool behaviour

| Rule | Detail |
| --- | --- |
| Read-only | Call **only** `get_incident` and/or `list_incidents`. Importing `create_incident` or `update_incident_status` in the tool module **fails** this milestone. |
| By id | `get_incident(incident_id)` → 0 or 1 row. Missing → `ok=False`, `error="not_found"`. |
| By filters | `list_incidents(...)` then keep at most **5** rows (already newest-first). No filters and no id → `not_found` (do not dump the whole table). |
| Timeout | `INCIDENT_LOOKUP_TIMEOUT_SECONDS = 5` (int, overridable via env of the same name). Run the manager call with a **5s** deadline (`concurrent.futures` wait, or equivalent). On expiry: `ok=False`, `error="timeout"`, `incidents=[]`. The graph must not hang. |
| Other errors | Catch, map to `error="unavailable"`. Log the exception; do not put `str(exc)` in state or the coordinator answer. |

## 6. Nodes (exact names)

Keep `intake`, `retrieve_policy`, `generate_policy`, `refuse`, `reject` as in 07.6.

| Node | Does | Must not |
| --- | --- | --- |
| `classify` | From `question` only: set `intent` + `incident_query`. No I/O. | Call retrieve, generate, or the incident manager |
| `lookup_incident` | Call the typed tool with `incident_query`; write `incident_result` | Call `retrieve` / `generate_answer` / `query()` / write APIs |
| `answer_incident` | Coordinator string **from `incident_result` only** (template; no LLM) | Invent status/category/dates; call RAG |
| `refuse_incident` | Fixed fallback (below). No LLM. | Guess a status |

### Classify (deterministic — no extra LLM)

Parse an id with a small regex: `#12`, `ticket 12`, `ticket #12`, `incident 12` (case-insensitive).

| `intent` | When |
| --- | --- |
| `incident` | An id **or** explicit live-record words (`ticket`, `incident`, `open tickets`) **and** the question is **not** a policy question |
| `rag` | Policy/procedure (cancel, no-show, insurance, referral, new-patient documents, Medicare/Medicaid fees, …) and **no** ticket/incident id |
| `both` | Policy **and** a ticket/incident id (or both kinds of ask) in the same question |

If empty after `intake`, do not run `classify` (existing `reject`).

If `intent=incident` but no id and no valid filter enum → still go to `lookup_incident`; the tool returns `not_found`.

Default when unsure and **no** id: `rag` (preserve 07.6). Weather-style questions stay RAG → empty retrieve → `refuse`.

## 7. Edges

```text
START → intake
  ├─ question empty     → reject → END
  └─ else               → classify
classify
  ├─ intent == incident → lookup_incident
  ├─ intent == both     → lookup_incident
  └─ intent == rag      → retrieve_policy
lookup_incident
  ├─ intent == incident and result.ok     → answer_incident → END
  ├─ intent == incident and not result.ok → refuse_incident → END
  └─ intent == both                       → retrieve_policy
retrieve_policy
  ├─ len(context) == 0  → refuse → END
  └─ else               → generate_policy → END
```

`both` always continues to RAG after the tool, even when the lookup failed. `generate_policy` / `refuse` then **prepend or append** one honest ticket sentence from `incident_result` (success facts or the fallback). Do not let the LLM invent the ticket half.

Named routers: `route_after_intake`, `route_after_classify`, `route_after_lookup`, `route_after_retrieve`.

---

## 8. Fallback copy (exact)

When the tool times out, errors, or finds nothing, the coordinator-facing ticket sentence is:

```text
I couldn't confirm that ticket's status right now
```

Never a fabricated `open` / `in_progress` / `resolved` / `discarded`. RAG refusals still use existing `NO_INFORMATION`.

## 9. Traces

Same path: `data/eval/agent_traces/{run_id}.json`. Extend the JSON:

```json
{
  "run_id": "uuid",
  "path": ["intake", "classify", "lookup_incident", "answer_incident"],
  "question": "…",
  "intent": "incident",
  "sources_used": ["incident"],
  "context_sources": [],
  "incident_ids": [12],
  "incident_error": null,
  "answer": "…",
  "error": null
}
```

| Field | Rule |
| --- | --- |
| `path` | Real node order from state `path` (not 07.6 `infer_path` guesses) |
| `sources_used` | `["rag"]` and/or `["incident"]` in the order they ran |
| `context_sources` | RAG `source_document` values (may be `[]`) |
| `incident_ids` | ids actually returned (`[]` on miss/timeout) |
| `incident_error` | `null` or `not_found` / `timeout` / `unavailable` |

Do **not** put `description` in the trace file or `GET /agent/traces/{run_id}` (operational free text). Id, status, category, origin, branch, dates may appear in `answer` only.

Update `infer_path` or delete it; traces must not claim `retrieve_policy` on a tool-only run.
