## 2. Locked product rules

**Departments** (only these `department_id` values; `compliance` always):

| `department_id` | Owner | Role this part |
| --- | --- | --- |
| `revenue` | Tom Callahan | Financial terms, currency, payment, ticket owner |
| `clinical` | Dr. Marcus Reid | Clinic/staff capacity vs covered population |
| `compliance` | Claire Whitfield | HIPAA vs UK GDPR; BAA (US) or DPA (UK) |

Unknown department names in the PDF → **ignore**. Do not invent ids.

**Part 1 ticket `status` only:** `analyzing` \| `discarded` \| `intake_complete`.

| Status | When |
| --- | --- |
| `analyzing` | Upload accepted; convert + graph running |
| `discarded` | Not a HealthCore RFP **or** uncaught pipeline crash (`discard_reason` distinguishes) |
| `intake_complete` | Synthesizer persisted; Sales can read key aspects |

**Classifier accept:** institutional request for HealthCore services — occupational health, corporate wellness, or referral partnership. Formal PDF **and** informal email-as-PDF both accept.

**Classifier reject:** vendor/product pitch (e.g. EHR sale), not a client RFP. Stop the graph. Do not run workers.

**PHI:** no patient name, MRN, NHS number, DOB, diagnosis, or identifier in DB columns, logs, traces, Markdown persisted for agents, HTTP, or UI — real or illustrative. Scan converted Markdown with `contains_phi` **before** any agent. Redact hits (`[REDACTED]`). Set `phi_detected=true`. Compliance `key_aspects` must flag human review. Never pass the original PHI span to workers or the UI.

**Missing figures:** `open_questions`; never invent headcount, budget, or clinics.

**Worker contradictions:** synthesizer does **not** average or invent consensus. Prefer quoted extracts; put conflicts in `open_questions`.

**False-negative discard:** stay `discarded` with `discard_reason=not_an_rfp`. Operator re-uploads. Tests lock the three CONTEXT PDFs (or markdown fixtures of the same cases).

**Async:** `POST` must **not** run the graph. Create row + write PDF + `202` `{ticket_id, status}`. Run `rfp_intake_graph` via FastAPI `BackgroundTasks` (same process; no new Compose worker, no Prefect for Part 1). Crash: `status=discarded`, `discard_reason=pipeline_error`, `error_code=pipeline_error` (no PHI in `error_code`/messages).

## 4. Graph (dedicated `rfp_intake`)

State (no PHI): `ticket_id`, `pdf_path`, `markdown` (redacted), `is_rfp`, `discard_reason`, `metadata`, `extracts` (`department_id` → text), `worker_results`, `synthesizer`, `phi_detected`, `error_code`.

```text
START → convert → classify
  is_rfp false → persist discarded → END
  is_rfp true  → orchestrate → [revenue | clinical | compliance workers in parallel] → synthesize → persist intake_complete → END
```

| Node | Does |
| --- | --- |
| `convert` | MarkItDown → Markdown; `contains_phi` + redact; `py-readability-metrics` on **redacted** Markdown (Flesch-Kincaid, Gunning Fog, and whatever else the lib returns — cost signal, not a literary grade); write `data/raw/rfp/{ticket_id}.md` |
| `classify` | Structured `{is_rfp, reason, program_type?}`. LLM optional; **deterministic fallback** required so pytest needs no live key. Reject vendor EHR/software pitches. |
| `orchestrate` | Always queue `revenue`, `clinical`, `compliance`. Fill `extracts` via headings/keywords. Drop unknown depts. |
| workers | Input: **shared metadata + that department’s extract only**. Output: `key_aspects` (bullet facts present in extract) + `open_questions`. No invented volumes. |
| `synthesize` | Sales-facing “ask whom”: Tom Callahan / Dr. Marcus Reid / Claire Whitfield. `departments_needed` always includes `compliance`. Build `handoff`. |
| persist | SQLModel commit; PHI scan all text fields; refuse write if scan hits. |

## 5. Postgres (SQLModel, same engine)

Register models in `init_inventory_schema()` (`import rfp.models`). Add `"rfp"` to hatch `only-include`. Do not create a second engine.

**`rfp_tickets`**

| Column | Notes |
| --- | --- |
| `ticket_id` | UUID PK, string |
| `rfp_id` | FK, nullable until metadata row exists |
| `status` | `analyzing` \| `discarded` \| `intake_complete` |
| `discard_reason` | `not_an_rfp` \| `pipeline_error` \| null |
| `error_code` | `pipeline_error` \| null |
| `phi_detected` | bool, default false |
| `raw_pdf_path` | `data/raw/rfp/{ticket_id}.pdf` |
| `markdown_path` | `data/raw/rfp/{ticket_id}.md` or null |
| `handoff_json` | Part 2 contract (null until `intake_complete`) |
| `created_at` / `updated_at` | timestamptz |
| `created_by` | JWT `UserPublic.id` string |

**`rfp_metadata`** (1:1 ticket; **never** a patient field)

`client_name`, `client_country` (`US` \| `UK` \| `unknown`), `program_type` (`occupational_health` \| `corporate_wellness` \| `referral_network` \| `unknown`), `covered_population` (int \| null), `deadline` (date/text \| null), `budget_range` (text \| null), `currency` (`USD` if US, `GBP` if UK, else null), `departments_needed` (JSON list; always include `compliance`), `readability` (JSON of metric name → number).

**`rfp_department_sections`**

`ticket_id`, `department_id` (`revenue` \| `clinical` \| `compliance`), `key_aspects` (text/JSON list), `open_questions` (JSON list). Nullable for later parts: `draft_content`, `evaluation_results` (JSON; include `contains_phi: bool`), `approval_status`, `approver`, `approved_at`. Part 1 does not fill drafts/approvals. If `phi_detected`, set compliance `evaluation_results.contains_phi=true`.

Gitignore: `data/raw/rfp/*.pdf`, `data/raw/rfp/*.md`.

## 6. Handoff (Part 2 reads this; no second API)

On `intake_complete`, `handoff_json` **must** include:

```json
{
  "ticket_id": "<uuid>",
  "phi_detected": false,
  "metadata": { },
  "departments": [
    {
      "department_id": "revenue",
      "owner": "Tom Callahan",
      "key_aspects": [],
      "open_questions": []
    }
  ],
  "synthesizer_summary": "what to ask whom"
}
```

Always three department objects. Part 2 starts from `ticket_id` + this payload; **do not re-parse the PDF**.

## 7. HTTP (existing `services/api`, JWT)

Prefix `/rfp`. Register in `app/main.py`. `python-multipart` already present.

| Method | Path | Behavior |
| --- | --- | --- |
| `POST` | `/rfp/tickets` | Multipart field `file`, PDF only. Save `data/raw/rfp/{ticket_id}.pdf`. Insert `status=analyzing`. Schedule background graph. **202** `{ticket_id, status}`. Reject non-PDF **400**. |
| `GET` | `/rfp/tickets/{ticket_id}` | Ticket + metadata + readability + `phi_detected` + `discard_reason` + `handoff_json` if complete. **404** if missing. |
| `GET` | `/rfp/tickets/{ticket_id}/sections` | Three sections (`key_aspects`, `open_questions`, owners). Empty lists while `analyzing`. |

No PHI in error `detail`. Sanitize like other routes.

## 8. Backoffice (`uis/backoffice` only)

- Nav item **RFP intake** → `/rfp`.
- Authenticated page: PDF file input, submit, then poll `GET` every ~3s while `status=analyzing`.
- Labels (not raw enums): Analyzing / Discarded / Intake complete. Discard copy: not-an-RFP vs pipeline error vs PHI flagged.
- On `intake_complete`: per-department `key_aspects`, `open_questions`, owner names. Sales must know **what to ask whom** without the PDF.
- BFF `app/api/rfp/tickets` (+ `[ticket_id]`, `sections`) → FastAPI. Client never calls `:8000`. Forward `Authorization`. Reuse `INVENTORY_API_URL` origin (same API).
- Do not render stored Markdown or PDF text in the UI.

## 10. Tests (`tests/pipelines/test_rfp_intake.py`)

No live LLM. Markdown (or tiny PDF) fixtures — **no real patient identifiers** in the repo; PHI fixture uses clearly fake tokens that `contains_phi` already matches (e.g. `patient Jane` + `diagnosed`).

| Case | Expect |
| --- | --- |
| Formal (Meridian / occupational / US / 800) | `is_rfp=true` → workers run; `revenue`+`clinical`+`compliance`; USD/BAA in compliance aspects or questions |
| Informal (Thames Valley / referral / UK) | `is_rfp=true`; GBP/DPA |
| Invalid EHR vendor pitch | `is_rfp=false`; ticket would be `discarded`; **no** worker key_aspects |
| Worker + missing volume | `open_questions` non-empty; no invented integer population |

UI: upload the three CONTEXT PDFs when files exist; confirm poll `analyzing` → `intake_complete` (1, 2) or `discarded` (3).
